# HIJET MONITOR（ハイゼット ジャンボ用 ESP32 見守り装置）

ESP32 DevKit V1（30 ピン）と専用基板（`hardware/`）で、軽トラの見守りと自動ロックをする。
通知はスマホの **ntfy** アプリに届き、ntfy から指示も送れる。エンジンスターターは使わない。

## できること

| 機能 | 内容 | 必要なもの |
|---|---|---|
| 自動ロック | キー（BLE ビーコン）が離れたら、ドアが閉まっていれば施錠信号を出す。開いていたら閉まった時点で施錠 | ビーコン、施錠信号・ドア信号の配線 |
| 侵入検知 | キーが離れているのにドアが開いた → 緊急通知（ブザー警報は任意） | ドア信号 |
| 揺れ検知 | 警戒中に車体が揺れた → 通知（駐車モードで眠っている間は働かない） | MPU6050 |
| ドアの開けっぱなし | キーが無いままドアが 5 分開いている → 通知 | ドア信号 |
| バッテリー | 低電圧、始動時の電圧の落ち込み（劣化の目安）、走行中の充電不良 → 通知。かなり下がったら省電力で休止 | （基板のみ） |
| OBD-II | 水温の異常、エンジン警告灯 → 通知。回転数でエンジン稼働を判定 | OBD-II ケーブル |
| 稼働時間・オイル | エンジン稼働時間を積算し、オイル交換時期を通知 | （OBD か電圧） |
| 走行記録 | 走行ごとの時間・距離・最高速度と駐車位置（地図リンク） | GPS |
| 車内環境 | 高温・低温 → 通知 | BME280 |
| 毎日の報告 | 20 時に状態をまとめて通知 | — |
| 盗難の検知 | **キーが無いのに ACC が入った**（リレーアタックなど）→ 緊急通知して、位置を 3 分ごとに通知（追跡）。駐車中は、J8 の GPS で 15 分ごとに位置を確かめ、150m 以上動いていたら通知 | GPS（追跡・移動の確認） |
| 点検の予定 | 車検・点検・タイヤ交換などを日付か走行距離で登録。30 日前・7 日前・前日・当日（距離は 500km 前・100km 前・到達）に通知 | 距離は GPS |
| 凍結の注意 | 朝 5〜9 時に車内が 1℃ 以下なら通知（1 日 1 回） | BME280 |
| 見張りと更新の保護 | 固まったら 30 秒で自動的に再起動し、理由を通知。OTA で更新した版が 10 分以内に ntfy と通信できなければ、前の版に自動で戻す | — |
| ダッシュボード | 電圧・車内温度の 24 時間グラフ、キー・ドア・警戒などの状態、駐車位置の地図、通知の履歴。ボタンで施錠・設定の切り替え。家からでも見られる | — |
| 駐車モード | キーが離れて 10 分たったら深く眠り、駐車中の消費電流を減らす。ドアが開く・ACC ON ですぐ起きる。15 分ごとに起きて指示と電圧を確認 | — |

## スマホからの指示

ふだんは**ダッシュボードの操作ボタン**から送る。ダッシュボードは指示に時刻と署名（「指示の鍵」による HMAC）を付けるので、指示のトピックを他人に読まれても、まねて送ったり使い回したりできない。

ntfy アプリから手で「`暗証番号 指示`」（例：`1234 status`）と送れるのは、`status`・`state`・`scan`・`beep`・`lock` だけ（ほかの指示は署名が必要）。

| 指示 | 内容 |
|---|---|
| `status` | 現在の状態（電圧・エンジン・車内温度・キー・ドア・稼働時間など） |
| `scan` | 近くの BLE 機器の一覧（ビーコンの MAC アドレスを調べるとき） |
| `lock` | 今すぐ施錠信号を出す |
| `pause 60` / `pause` / `resume` | 自動ロックを 60 分 / 再開まで止める、再開する |
| `autolock on\|off` | 自動ロックの有効・無効 |
| `alarm on\|off` | 侵入・揺れの通知の有効・無効 |
| `siren on\|off` | 侵入時にブザーを鳴らすか（初期値 off） |
| `park on\|off` | 駐車モードの有効・無効（初期値 on） |
| `beep` / `silence` | ブザーを鳴らす / 止める |
| `track on\|off` | 追跡（位置を 3 分ごとに通知）の開始・終了 |
| `oilreset` | オイル交換したことを記録 |
| `state` | ダッシュボードに最新の状態を送る（通知は出さない） |
| `setup` | 設定モードを開始（10 分間） |

解錠の指示はない（防犯のため）。

駐車モードで眠っている間は、指示は**最大 15 分遅れて**実行される（15 分ごとに起きて読みに行くため）。

## 駐車モード

キーが離れて施錠した後は、Wi-Fi と BLE を止めてディープスリープし、駐車中のバッテリーの消費を抑える。

| 項目 | 内容 |
|---|---|
| 眠る条件 | キーが離れている・ACC OFF・ドアが閉まっている・施錠待ちや未送信の通知がない・自動ロックの一時停止中でない。この状態が 10 分続いたら眠る |
| すぐ起きる | ドアが開いた（15 秒以内にキーが見つからなければ侵入として通知）、ACC ON |
| 時間で起きる | 15 分ごと。指示の確認、電圧の確認、20 時の報告。キーが近くにあればそのまま起きている |
| 眠る前に止めるもの | Wi-Fi・BLE、GPS（待機命令）、MPU6050・BME280（スリープ）、出力とブザー（LOW に固定） |
| 眠っている間にできないこと | 揺れ検知、指示の即時実行 |

消費電流の見積もり（12V 側。**実測していない**）：

| 状態 | 見積もり | 1 日あたり |
|---|---|---|
| 駐車モードなし（Wi-Fi・BLE を動かし続ける） | 50〜65mA | 1.2〜1.6Ah |
| 駐車モード（眠っている間＋15 分ごとの起動） | 5〜13mA | 0.12〜0.3Ah |

眠っている間の電流の大部分は、ESP32 本体ではなく、DevKit の 3.3V レギュレーター（AMS1117）と電源 LED、DC-DC の待機電流。
取り付けたら、12V の線にテスターを直列に入れて（mA レンジ）、眠っている間の電流を測ること。GPS が待機命令に対応していないと 25〜50mA 増える。
間隔などは `config.h` の `PARK_*` で変えられる。

## セットアップ

1. スマホに **ntfy** アプリを入れる。トピック名を 3 つ決める（通知・指示・状態。推測されない長いランダムな文字列）。アプリでは**通知のトピックだけ**を購読する。
2. 書き込む。**Arduino IDE** か **PlatformIO** のどちらでもよい（下の「書き込み方」）。初回は USB。2 回目からは、ダッシュボードから離れた場所でも更新できる（下の「離れた場所から更新する」）。
3. 初めて起動すると、ESP32 が **設定モード**になり、Wi-Fi「`HIJET-SETUP-xxxx`」（パスワード `hijet-setup`）を出す。スマホでつなぐと設定画面が開くので、次を入力して保存する（保存すると再起動する）。
   - Wi-Fi（主と予備の 2 つまで）
   - ntfy のサーバーと 3 つのトピック（ntfy のアカウントを使うならアクセストークン）
   - 暗証番号（数字 4〜8 桁）、OTA のパスワード
   - キー（BLE ビーコン）。設定画面の「近くの BLE 機器を表示」から選べる
4. ダッシュボード（`dashboard/`）を開き、同じサーバーとトピック、暗証番号を入れる（[dashboard/README.md](dashboard/README.md)）。
5. `src/config.h` のしきい値（施錠信号の長さ `LOCK_PULSE_MS` など）を実車に合わせる。電圧の補正係数は設定画面で入れる。

設定を変えたいときは、設定モードに入り直す。入り方は次のどれか。
- DevKit の **BOOT ボタンを 3 秒押す**（ブザーが 2 回鳴る）
- ダッシュボードの「設定モードを開始」か、指示 `setup`
- **ACC ON のまま 3 分 Wi-Fi につながらない**とき（スマホを買い替えてテザリングの名前が変わったときなど）は自動で入る

設定済みなら、保存には今の暗証番号が必要（近くにいる他人に書き換えさせないため）。5 回続けて間違えると 5 分間受け付けない（くり返すたびに倍、最長 1 時間）。設定モードは 10 分で自動的に終わる。
机の上で何度も書き込み直すときは、`src/secrets.example.h` を `src/secrets.h` にコピーして値を書いておくと、初回の設定の入力を省ける（一度保存した設定は上書きしない）。

USB で書き込むときは、基板の 12V（J1）を外すこと。

### 書き込み方：Arduino IDE

1. Arduino IDE 2 を入れる。「ファイル → 基本設定」の「追加のボードマネージャの URL」に
   `https://espressif.github.io/arduino-esp32/package_esp32_index.json` を入れる。
2. ボードマネージャで「esp32 by Espressif Systems」の **2.0.17** を入れる（3.x ではビルドできない）。
3. ライブラリマネージャで次の版を入れる（依存するライブラリも聞かれたら一緒に入れる）。
   - NimBLE-Arduino **1.4.3**（2.x は使い方が違うのでビルドできない）
   - ArduinoJson **7.2.1**
   - Adafruit BME280 Library **2.2.4**
4. このフォルダ（`esp32_engine_starter`）の `esp32_engine_starter.ino` を開く。中身はほぼ空だが、
   `src/` の中も一緒にビルドされる。フォルダ名を変えると開けないので、名前はそのままにする。
5. 「ツール」で次を選ぶ。
   - ボード：**ESP32 Dev Module**
   - Partition Scheme：**Minimal SPIFFS (1.9MB APP with OTA/190KB SPIFFS)**（既定のままだと大きすぎて書き込めない）
   - シリアルポート：ESP32 の COM ポート
6. 「書き込み」（→）を押す。`Connecting...` で止まったら、DevKit の BOOT ボタンを押したままにし、書き込みが始まったら離す。
7. 「ツール → シリアルモニタ」を **115200 baud** で開く。`setup portal: HIJET-SETUP-xxxx` と出れば動いている。

### 離れた場所から更新する（同じ Wi-Fi でなくてよい）

1. PlatformIO で **Build** する。できたファームウェアが `build/firmware.bin` にコピーされる。
2. ダッシュボードの「**ファームウェアを更新**」を押して、`build/firmware.bin` を選ぶ。
3. ファイルは ntfy の指示のトピックに添付して送られる（ntfy.sh では 3 時間で消える）。ESP32 は次に指示を読んだとき
   （休止中なら最大 15 分後）にダウンロードして書き込み、再起動する。
4. 新しい版が ntfy とやり取りできれば「ファームウェアを更新しました」と届く。10 分以内にできなければ、自動で前の版に戻る。

指示は「指示の鍵」で署名し、ファイルの SHA-256 も署名に含めるので、他人が別のファイルを書き込ませることはできない。

### push で自動更新する

`src/config.h` の `FW_VERSION` を変えて push すると、GitHub Actions（`/.github/workflows/hijet-ota.yml`）がテスト・ビルドして、上と同じ遠隔更新を送る。
GitHub の Secrets に `HIJET_CMD_KEY`・`HIJET_NTFY_SERVER`・`HIJET_CMD_TOPIC`（自前のサーバーなら `HIJET_NTFY_TOKEN` も）を入れておく。

### 書き込み方：PlatformIO

`pio run -e esp32dev -t upload`（ボード・パーティション・ライブラリの版は `platformio.ini` で決めてある）。

## Ottocast の GPS を使う

Ottocast（中身は Android）に GPS が入っていれば、その位置を Wi-Fi で ESP32 に送れる。J8 の GPS モジュールは無くてもよい。

1. Ottocast の地図アプリで、スマホをつながずに現在地が出るか確かめる（出なければ GPS が無い機種）。
2. Ottocast に、位置を NMEA で UDP 送信するアプリを入れる（例：**GPSd Forwarder**）。
3. 送り先を ESP32 の IP アドレス（ダッシュボードの「通信」に表示）、ポートを **10110** にする。
4. Ottocast と ESP32 を同じ Wi-Fi（車内のテザリング）につなぐ。

注意
- テザリングによっては、つないだ機器どうしの通信ができない。
- ESP32 の IP アドレスが変わると届かなくなる。スマホのテザリングは同じ機器には同じアドレスを配ることが多いが、変わったら設定し直す。
- Ottocast は ACC OFF で電源が切れるので、**最後に受け取った位置を駐車位置**とする。駐車中の移動（レッカーなど）の確認には、J8 の GPS モジュールが必要。

## 構成

- `src/` … ファームウェア（Arduino フレームワーク）
  - `main.cpp` 全体の動作・通知・指示 / `io` 入出力 / `buzzer` / `battery` / `ble_presence` /
    `sensors`（BME280・MPU6050）/ `obd`（CAN）/ `gps` / `notifier`（ntfy）/
    `settings`（設定の保存）/ `portal`（設定モードの画面）/ `ca_roots.h`（ntfy の証明書を確かめるルート証明書）
- `src/logic/` … PC でテストできる判定ロジック（在・不在、ビーコン、チャタリング除去、通知の間引き、
  NMEA、OBD、バッテリー診断、駐車モード、履歴、設定の書式、指示の署名、点検の予定）
- `test/` … 上記のテスト
- `dashboard/` … ダッシュボード（ブラウザで開く 1 枚の HTML）。詳しくは [dashboard/README.md](dashboard/README.md)
- `hardware/` … 基板（ガーバー・部品表・組み立て手順）。詳しくは [hardware/README.md](hardware/README.md)
- `server/` … 状態・指示用の自前の ntfy サーバー（Docker・Cloudflare Tunnel）。詳しくは [server/README.md](server/README.md)
- `obsidian/` … プロジェクト全体のまとめと履歴（Obsidian のノート。このフォルダを保管庫として開く）

## 確認したこと・していないこと

- **確認済み：** ロジックのテスト 25 件が合格。ESP32 用の実際のコンパイラ（arduino-esp32 2.0.17、
  PlatformIO の `espressif32@6.9.0` と同じコア）で、PlatformIO と arduino-cli（Arduino IDE と同じ仕組み）の
  どちらでも警告なしでビルドできる（フラッシュ 69%、RAM 19%）。
- **未確認：** 実機での動作（ntfy への通知、BLE、CAN、GPS、センサー、スリープからの復帰）。
  特に OBD-II は、ハイゼットが標準の要求（500kbps、ID 0x7DF）に応答するかを実車で確かめる必要がある。
- ntfy との通信は暗号化し、サーバー証明書もルート証明書で確かめている（証明書の期限は確かめない。`notifier.cpp` を参照）。
