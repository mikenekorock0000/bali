# HIJET MONITOR（ハイゼット ジャンボ用 ESP32 見守り装置）

ESP32 DevKit V1（30 ピン）と専用基板（`hardware/`）で、軽トラの見守りと自動ロックをする。
通知はスマホの **ntfy** アプリに届き、ntfy から指示も送れる。エンジンスターターは使わない。

## できること

| 機能 | 内容 | 必要なもの |
|---|---|---|
| 自動ロック | キー（BLE ビーコン）が離れたら、ドアが閉まっていれば施錠信号を出す。開いていたら閉まった時点で施錠 | ビーコン、施錠信号・ドア信号の配線 |
| 侵入検知 | キーが離れているのにドアが開いた → 緊急通知（ブザー警報は任意） | ドア信号 |
| 揺れ検知 | 警戒中に車体が揺れた → 通知（駐車モードで眠っている間は働かない） | MPU6050 |
| ドアの開けっぱなし | キーが無いままドアが 5 分開いている → 通知 | ドア信号 |
| バッテリー | 低電圧、始動時の電圧の落ち込み（劣化の目安）、走行中の充電不良 → 通知。かなり下がったら省電力で休止 | （基板のみ） |
| OBD-II | 水温の異常、エンジン警告灯 → 通知。回転数でエンジン稼働を判定 | OBD-II ケーブル |
| 稼働時間・オイル | エンジン稼働時間を積算し、オイル交換時期を通知 | （OBD か電圧） |
| 走行記録 | 走行ごとの時間・距離・最高速度と駐車位置（地図リンク） | GPS |
| 車内環境 | 高温・低温 → 通知 | BME280 |
| 毎日の報告 | 20 時に状態をまとめて通知 | — |
| 駐車モード | キーが離れて 10 分たったら深く眠り、駐車中の消費電流を減らす。ドアが開く・ACC ON ですぐ起きる。15 分ごとに起きて指示と電圧を確認 | — |

## スマホからの指示

ntfy アプリで**指示用トピック**を購読し、「`暗証番号 指示`」の形で送る（例：`1234 status`）。

| 指示 | 内容 |
|---|---|
| `status` | 現在の状態（電圧・エンジン・車内温度・キー・ドア・稼働時間など） |
| `scan` | 近くの BLE 機器の一覧（ビーコンの MAC アドレスを調べるとき） |
| `lock` | 今すぐ施錠信号を出す |
| `pause 60` / `pause` / `resume` | 自動ロックを 60 分 / 再開まで止める、再開する |
| `autolock on\|off` | 自動ロックの有効・無効 |
| `alarm on\|off` | 侵入・揺れの通知の有効・無効 |
| `siren on\|off` | 侵入時にブザーを鳴らすか（初期値 off） |
| `park on\|off` | 駐車モードの有効・無効（初期値 on） |
| `beep` / `silence` | ブザーを鳴らす / 止める |
| `oilreset` | オイル交換したことを記録 |

解錠の指示はない（防犯のため）。

駐車モードで眠っている間は、指示は**最大 15 分遅れて**実行される（15 分ごとに起きて読みに行くため）。

## 駐車モード

キーが離れて施錠した後は、Wi-Fi と BLE を止めてディープスリープし、駐車中のバッテリーの消費を抑える。

| 項目 | 内容 |
|---|---|
| 眠る条件 | キーが離れている・ACC OFF・ドアが閉まっている・施錠待ちや未送信の通知がない・自動ロックの一時停止中でない。この状態が 10 分続いたら眠る |
| すぐ起きる | ドアが開いた（15 秒以内にキーが見つからなければ侵入として通知）、ACC ON |
| 時間で起きる | 15 分ごと。指示の確認、電圧の確認、20 時の報告。キーが近くにあればそのまま起きている |
| 眠る前に止めるもの | Wi-Fi・BLE、GPS（待機命令）、MPU6050・BME280（スリープ）、出力とブザー（LOW に固定） |
| 眠っている間にできないこと | 揺れ検知、指示の即時実行 |

消費電流の見積もり（12V 側。**実測していない**）：

| 状態 | 見積もり | 1 日あたり |
|---|---|---|
| 駐車モードなし（Wi-Fi・BLE を動かし続ける） | 50〜65mA | 1.2〜1.6Ah |
| 駐車モード（眠っている間＋15 分ごとの起動） | 5〜13mA | 0.12〜0.3Ah |

眠っている間の電流の大部分は、ESP32 本体ではなく、DevKit の 3.3V レギュレーター（AMS1117）と電源 LED、DC-DC の待機電流。
取り付けたら、12V の線にテスターを直列に入れて（mA レンジ）、眠っている間の電流を測ること。GPS が待機命令に対応していないと 25〜50mA 増える。
間隔などは `config.h` の `PARK_*` で変えられる。

## セットアップ

1. スマホに **ntfy** アプリを入れ、通知用と指示用の 2 つのトピックを作る。名前は推測されない長いランダムな文字列にする。
2. `src/secrets.example.h` を `src/secrets.h` にコピーし、Wi-Fi、ntfy のトピック、暗証番号、OTA パスワードを書く。
3. PlatformIO で書き込む：`pio run -e esp32dev -t upload`（初回は USB。2 回目からは Wi-Fi 経由の OTA でもよい）。
4. ビーコンを近くに置いて ntfy で `1234 scan` を送り、一覧から MAC（または `uuid:...`）を `secrets.h` の `BEACON_RULES` に書いて書き込み直す。
5. `src/config.h` のしきい値（電圧の補正 `VBAT_CAL`、施錠信号の長さ `LOCK_PULSE_MS` など）を実車に合わせる。

USB で書き込むときは、基板の 12V（J1）を外すこと。

## 構成

- `src/` … ファームウェア（Arduino フレームワーク）
  - `main.cpp` 全体の動作・通知・指示 / `io` 入出力 / `buzzer` / `battery` / `ble_presence` /
    `sensors`（BME280・MPU6050）/ `obd`（CAN）/ `gps` / `notifier`（ntfy）
- `lib/starter_logic/` … PC でテストできる判定ロジック（在・不在、ビーコン、チャタリング除去、通知の間引き、
  NMEA、OBD、バッテリー診断）
- `test/` … 上記のテスト
- `hardware/` … 基板（ガーバー・部品表・組み立て手順）。詳しくは [hardware/README.md](hardware/README.md)

## 確認したこと・していないこと

- **確認済み：** ロジックのテスト 16 件が合格。ESP32 用の実際のコンパイラ（arduino-esp32 2.0.17、
  PlatformIO の `espressif32@6.9.0` と同じコア）で、警告なしでビルドできる（フラッシュ 64%、RAM 19%）。
- **未確認：** 実機での動作（ntfy への通知、BLE、CAN、GPS、センサー、スリープからの復帰）。
  特に OBD-II は、ハイゼットが標準の要求（500kbps、ID 0x7DF）に応答するかを実車で確かめる必要がある。
- ntfy との通信は暗号化しているが、サーバー証明書の検証は省略している（`notifier.cpp` の注意書きを参照）。
