# トラブルシューティング

[[HIJET MONITOR]] ／ 関連：[[動作確認の記録]]・[[ファームウェア#シリアル出力（115200bps）]]

困ったら、まず Monitor（115200bps）の表示を見る。

## 実際に起きたこと

### 起動 2 分後に省電力モードに落ちる
- 原因：USB だけだと電圧入力が空いて 1.5V 前後に読め、低電圧と判断していた。
- 対策：6V 未満は 12V 未接続とみなす。設定モード中も眠らない。（1.2.0 で修正）

### PlatformIO の Build で native が FAILED
- 原因：PC 用のテスト環境まで動いていた。ESP32 の側は SUCCESS。
- 対策：既定の環境を esp32dev だけにした。

### 設定モードの Wi-Fi にすぐ切れる
- 症状：`HIJET-SETUP` は一覧に出るが、一瞬つながって「接続できませんでした」。キャプティブ画面が一瞬出て消える。
- **本当の原因**：設定画面を開いた瞬間に、時間の引き算が負になり（符号なしで巨大な値）、「10 分たった」と判断して設定モードを終えていた。未設定のときは時間切れを見ないので、初回の設定ではうまくいった。
- ログの手がかり：`request handler not found`（iPhone がつながった）の直後に `netstack cb reg failed`（設定モードが終わった）、続いて `wifi=1`。
- 対策：時刻を取り直して符号付きで比べる。終わったときは `setup portal: 終了` と出す。
- ついでに：iPhone のテザリングを出しているときは、その iPhone は別の Wi-Fi につなげない。設定中は ESP32 がつながらない Wi-Fi を探さない・Bluetooth を止める。
- 遠回りした仮説（チャンネルの移動・Bluetooth の干渉）は、どれも決め手ではなかった。

### 鍵の欄に暗証番号が入力できない
- 原因：鍵の欄は表示専用で、暗証番号はページ下の「確認」欄から取っていた。
- 対策：鍵の枠に暗証番号の入力欄を付け、トピックと一緒に表示する。

### ダッシュボードが「接続中…」のまま
- 原因 1：最初の状態の送信が、起動から 5 分後だった。→ Wi-Fi につながったらすぐ送るように変更。
- 原因 2：ダッシュボードの「状態のトピック」の名前が違っていた。→ 設定画面の表示と見比べて直した。
- 確かめ方：Monitor の `[state] 送信 200` と、ブラウザで `https://ntfy.sh/<状態のトピック>/json?poll=1`。

### ACC やドアを変えても通知が来ない
- 故障ではない。通知はキーが近くにないときの異常だけ。ビーコン未登録だと警戒しない。

### 「異常で再起動しました（ウォッチドッグ）」
- 2026-10-25 16:52 に 1 回。原因の候補：暗号化の手続きが最長 120 秒待ち、loop が止まった。
- 対策：10 秒で諦める（1.2.1）。また起きたら記録する。

### 遠隔更新の「更新しました」がすぐ来ない
- 正常。新しい版が 60 秒以上動いて ntfy とやり取りできてから送る。

## よくある確認

| 症状 | 確かめること |
|---|---|
| ポートが見つからない | 充電専用ケーブル、USB ドライバ（CP2102 / CH340） |
| `Connecting...` で止まる | BOOT ボタンを押したまま書き込む |
| `wifi=0` のまま | テザリング ON、2.4GHz、「互換性を優先」、名前とパスワード |
| 通知が来ない | アプリのトピック名が通知のトピックと同じか |
| 指示が効かない | `[cmd]` が出るか、署名の判定の数字 |
| プルしたのに変わらない | Upload したか |
