# 発注前の検証結果（HIJET MONITOR v4）

`./build.sh` を実行するたびに、下の 1〜5 の検証がすべて自動で走ります。1 つでも問題があればガーバーは作られません。
各検証の生の出力は `drc_report.txt`・`pins_report.txt`・`mech_report.txt`・`sim_report.txt`・`fab_report.txt` にあります。

## 検証の結果

| # | 検証 | 方法 | 結果 |
|---|---|---|---|
| 1 | 配線ルール（DRC） | KiCad 7 の DRC。間隔 0.3mm、端から 0.5mm、穴どうしの距離、シルクの重なりなど | 違反 0・未接続 0 |
| 2 | ピン配置 | `check_pins.py`：生成スクリプトとは別に、データシートと購入したボードの写真から書き起こした表で 68 組の接続を照合。ファームウェアの `config.h` のピン番号 16 本とも照合。起動設定ピン（GPIO0/2/5/12/15）と入力専用ピン（34〜39）の誤用も確認 | 問題 0 |
| 3 | 部品の収まり | `check_mech.py`：部品の足の太さと穴径、ESP32 の下（直接はんだ付けで隙間 2.5mm）に部品がないこと、USB ケーブルのプラグが通る空間（高さ 1mm 超の部品なし）、端子台の差し込み口の向き、基板からのはみ出し | 問題 0 |
| 4 | 回路の数値 | `sim/`：ngspice によるシミュレーションと、データシート値による電源の計算 | 問題 0 |
| 5 | 製造データ | `check_fab.py`：ドリルファイルの穴の数・径が基板と一致するか、必要な層がそろっているか、ドリルマップが混ざっていないか | 問題 0 |

検証が見落とさないことも確かめた。わざと誤りを入れると、それぞれ検出される（CAN の送信・受信ピンの入れ替え、`config.h` のブザーのピン番号違い、穴に入らない太さの足、ESP32 の下に置いたコンデンサ、USB プラグの通り道に置いた抵抗と TVS）。

## 検証で見つかり、直した問題

| 問題 | 影響 | 修正 |
|---|---|---|
| （v4）秋月電子で買えない部品があった（OKI-78SR、3.5mm 端子台、P6KE22A、ポリスイッチ 0.75A） | 1 か所でそろわない | DC-DC を M78AR05-1、端子台を 5.08mm の TB112、ポリスイッチを RXEF090 に変更し、穴とレイアウトを合わせた。P6KE20A は DigiKey |
| （v4）M78AR05-1 の入力上限は 32V で、P6KE22A のクランプ 30.6V では余裕が少ない | サージで DC-DC が壊れるおそれ | TVS を **P6KE20A**（クランプ 27.7V、スタンドオフ 17.1V）に変更 |
| （v4）出力端子にサージ保護がなかった | 配線からのサージやリレーのコイルの逆起電力でフォトカプラが壊れるおそれ | 双方向 TVS **SMBJ45CA** を各出力に追加。フォトカプラは VCEO 80V の PC817 X 系 |
| （v4.1）RXEF090 が売り切れ。調べ直すと、RXEF の本体は幅 11〜13mm あり、基板の外形（幅 7.5mm）が小さすぎた | 隣の部品に当たる | RXEF110（幅 12.8mm・足 0.81mm）用の外形を作り、基板の上の端に移した |
| （v4.1）ポリスイッチは、トリップ電流（RXEF110 で 2.2A）未満なら切れずに流れ続ける | 1A の 1N5819 が過熱するおそれ | 逆接保護を 3A の **SB340LS** に変更 |
| （v4）入力の 2.2k は、35V（抑制後のロードダンプ）で発熱 0.5W 超 | 1/4W 抵抗の短時間の許容（0.625W）に近い | **3.3k** に変更（35V で 0.34W、12V で LED 3.2mA） |
| （v4）ESP32 をソケットで挿すと、車の振動で接触が悪くなるおそれ | 走行中のリセット・誤動作 | **直接はんだ付け**に変更。下の隙間が 2.5mm になるため、ESP32 の下にあった U9・C5・C6・R15 を外に移した |
| 電圧測定の分圧が 100k/22k だと、充電中（14.7V）に GPIO34 が 2.65V になる | ESP32 の ADC（11dB）が精度よく測れる範囲（約 2.45V まで）を超え、高い電圧ほど不正確になる | R2 を **18kΩ** に変更（14.7V で 2.24V、16V で 2.44V）。`config.h` の分圧比も変更 |
| ポリスイッチ 0.5A は、高温で保持電流が約 6 割に下がる | 夏の車内（85℃）では 0.3A 程度になり、Wi-Fi 送信などのピーク（9V 入力時 約 0.37A）で切れるおそれ | **0.75A** に変更（85℃でも約 0.45A） |
| 出力フォトカプラの LED 電流が 3〜4.5mA（470Ω） | 車両の施錠入力が数 mA〜10mA を必要とする場合に余裕が少ない | **330Ω** に変更（約 4〜5mA。受光側は 8〜9mA まで引ける） |
| R15（CAN 待機用の 10k）を立てて実装すると高さ約 10mm | ESP32 の下（ソケット使用時 約 11mm の隙間）に当たる | v3 では横置き。v4 では ESP32 の外に移したので立てて実装 |
| CAN 端子台 J7 が ESP32 の USB コネクタの正面にあった | USB ケーブルのプラグが端子台に当たり、挿せないおそれ | J7 を左にずらし、ブザー回りの部品も移動 |
| シルクの文字の線幅が 0.12mm | JLCPCB の推奨（0.153mm 以上）より細く、かすれるおそれ | 0.16mm に変更 |
| 自動配線の切れ端（0.25mm の配線）が 1 本 | 電気的にはつながっているが、DRC の警告 | T 字分岐で配線を分割し、切れ端を取り除く後処理を追加 |

## 発注・購入で間違えやすい点（部品表 `bom.csv` に秋月の URL 付きで記載）

| 部品 | 注意 |
|---|---|
| MCP2562 | **MCP2561 は不可**（5 番ピンの役割が違う）。秋月の MCP2562FD-E/P で可 |
| PC817 | 秋月の **PC817X3NSZ1B**（VCEO 80V、CTR 200〜400%）。VCEO 35V の古い品は出力 TVS のクランプ電圧に耐えない |
| 2SC1815 | 足の並びが **E-C-B** のもの。2N3904 などは並びが違うので不可 |
| 積層セラミック 0.1µF | 足の間隔 **2.5mm**。5.0mm 品は穴に合わない |
| 電子ブザー | **自励式（発振回路内蔵）5V、φ12mm、足の間隔 7.6mm**。秋月の UGCM1205XP の足の間隔はデータシートで確認できなかったので、届いたら原寸 PDF に当てて確認 |
| ポリスイッチ | **RXEF110**（72V）。RXE110（60V）でも可。名前の似た RUEF 系は耐圧 30V なので不可 |
| 端子台 | 秋月の **TB112（「縦」と書かれた品）**＝ねじが上、電線は基板と平行に横から入る。「横」と書かれた品（TB112a）は電線が上から入るので、この基板の向きと合わない |
| 電源の TVS | **P6KE20A**（末尾 A＝単方向）。秋月にないので DigiKey など。P6KE22A でも可 |
| 出力の TVS | **SMBJ45CA**（末尾 CA＝双方向）。SMAJ45A（単方向）は不可 |
| 電解コンデンサ C2 | φ6.3mm・高さ 5mm 程度の背の低いもの（振動対策） |
| ESP32 ボード | **30 ピンの DevKit V1（HW-394 など）**。38 ピンの DevKitC は付けられない |

## 実物でしか確かめられないこと

基板と部品が届いたら、次の順で確認してください。

1. **原寸 PDF（`hijet_starter_1to1.pdf`）を 100% で印刷**し、ESP32 ボード・端子台・ブザー・ポリスイッチ・DC-DC（M78AR05-1 の足の太さ）を当てて、穴の位置と端子台の差し込み口の向きを確認する（発注前にできればなお良い）。
2. 12V をつなぐ前に、テスターで 12V と GND の間がショートしていないことを確認する。
3. 12V をつなぎ、ESP32 をはんだ付けする前に 5V（J5 の 15 番）を測る。
4. ESP32 をはんだ付けし、シリアル出力で電圧の表示がテスターの実測と合うか確認する（合わなければ `VBAT_CAL` で補正）。
5. 車両側：施錠信号が「GND に落とすと施錠するタイプ」か、ドア信号が「開くと GND に落ちるタイプ」かを、配線図か電装店で確認する。
6. OBD-II：ハイゼットが標準の問い合わせ（500kbps、ID 0x7DF）に応答するかは、実車でしか分からない。応答しなくても、ほかの機能は動く。
7. 互換 ESP32 ボードによっては、USB と VIN が直結されているものがある。USB で書き込むときは必ず 12V を外す。
