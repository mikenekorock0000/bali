# HIJET MONITOR 技術説明書（第三者検証用）

ダイハツ ハイゼット ジャンボ エクストラ（S500P/S510P 系、CVT、キーフリー＋プッシュスタート、イモビライザー付き）に取り付ける、ESP32 を使った見守り装置です。
基板（v4、98×90mm、2 層）とファームウェア（Arduino-ESP32）の一式です。
**エンジンスターター機能はありません。** また、イモビライザーやスマートキーには一切関与しません。

このパッケージは**別の検証者に設計の誤りを探してもらうため**のものです。第 9 章に「検証してほしい点」と「確認できていない前提」をまとめています。

## 2. 機能

| 機能 | 内容 | 使う回路 |
|---|---|---|
| 自動ロック | 持ち主の BLE ビーコンが離れ、ドアが閉まっていたら、施錠信号を 400ms 出す | 絶縁出力 LOCK、絶縁入力 IN1（ドア） |
| 侵入検知 | ビーコンが無いのにドアが開いた → スマホに緊急通知（ブザーは任意） | IN1 |
| 振動検知 | 警戒中に加速度が変化 → 通知 | I2C の MPU6050（外付け） |
| バッテリー監視 | 低電圧、始動時の電圧降下、走行中の充電不良 → 通知。11.5V 以下でディープスリープ | 電圧測定 |
| OBD-II | 水温・エンジン警告灯・回転数を標準 PID で問い合わせ | CAN（MCP2562） |
| 走行記録 | 走行ごとの距離・最高速度・駐車位置 | UART の GPS（外付け） |
| 車内温度 | 高温・低温で通知 | I2C の BME280（外付け） |
| 通知・指示 | ntfy（HTTPS）で通知、指示用トピックをポーリングして指示を受ける | Wi-Fi |

車内の Wi-Fi（テザリングなど）につながっている前提です。解錠の指示はありません（防犯のため）。

## 4. 回路の詳細

部品番号は `netlist.txt` と基板のシルク印刷に一致します。

### 4.1 電源

| 部品 | 値 | 役割・根拠 |
|---|---|---|
| J1 | 3P 端子台 5.08mm | 1=BATT（+12V 常時電源）、2=GND、3=OUT（F1 通過後の 12V。入力回路の IN+ 用） |
| F1 | Bourns MF-RX110/72（または Littelfuse RXEF110） | 保持 1.1A・トリップ 2.2A・最大 72V。85℃で保持電流は約 6 割（0.66A）とみて、9V 入力時の最大 0.39A を上回る |
| D1 | SB340LS（40V 3A ショットキー、DO-15） | 逆接保護。F1 がトリップしないまま流れうる最大 2.2A に対して 3A。IFSM 80A |
| D2＋D12 | P4KE15A（単方向）＋P4KE6.8CA（双方向）を直列 | 電源ラインの TVS。直列のスタンドオフ 12.8＋5.8＝18.6V（充電電圧上限 14.8V より上）。クランプは 18.9A 時に 21.2＋約 8.8＝**約 30.0V**（P4KE6.8CA の 18.9A 時の電圧は VBR max 7.14V と Vc 10.5V@38A の間を直線補間）。DC-DC の入力上限 32V 以下 |
| C1 | 100µF 50V（φ8） | DC-DC の入力コンデンサ。M78AR 系のデータシートの注記「入力 28V 超では 22µF/50V 以上を付ける」を満たす |
| U1 | MINMAX M78AR05-1 | 三端子レギュレーター互換の DC-DC。入力 6.5〜32V、出力 5V 1A。ピン 1=Vin、2=GND、3=Vout |
| C2・C3 | 100µF 16V（φ6.3×5、背が低い品）・0.1µF | 5V の出力コンデンサ |

**消費電流の見積もり（5V 側のピーク）**：ESP32 の Wi-Fi 送信 350mA、MCP2562 70mA、GPS 50mA、ブザー 30mA、センサー 10mA、出力用 LED 26mA、合計 約 536mA。
DC-DC の効率を 80% とすると、12V 側の電流は 9V 入力で 0.39A、12V で 0.29A、14.7V で 0.23A です。

### 4.2 電圧測定

12V_F → R1 100k → VSENSE → R2 10k → GND（組み立て時に手持ちの都合で 18k から変更）。VSENSE には C4 0.1µF を付け、D3 BAT43（ショットキー）で 3V3 へクランプしています。VSENSE は GPIO34（ADC1）につながり、ADC は 11dB 減衰で使います。

| 電源電圧 | 9V | 12V | 14.7V | 16V | 24V（異常） | 30V（異常） | −14V（逆接） |
|---|---|---|---|---|---|---|---|
| GPIO34（ngspice） | 0.82V | 1.09V | 1.34V | 1.46V | 2.18V | 2.73V | −0.47V |

- 通常範囲（9〜16V）では、ADC の精度がよい 0.15〜2.45V に収まります。
- 異常電圧でもクランプにより絶対最大 3.6V 以下です。

### 4.3 絶縁出力 ×4（J2）

| 項目 | 内容 |
|---|---|
| 回路 | GPIO（HIGH で ON）→ 330Ω → PC817 の LED（アノード 1、カソード 2＝GND） |
| 出力 | フォトトランジスタのエミッタ（3）を J2 の「−」、コレクタ（4）を J2 の「＋」に出す |
| J2 の並び | 1=LOCK−、2=LOCK＋、3=OUT2−、4=OUT2＋、… |
| LED 電流 | 3.9〜4.7mA |
| 出力電流 | 50mA 以下（リレーは直接駆動しない想定） |
| 保護 | 各チャンネルの＋と−の間に双方向 TVS **SMBJ45CA**（D8〜D11、SMB 表面実装）。スタンドオフ 45V、クランプ 72.7V。PC817X 系の VCEO 80V 以下 |
| 想定する使い方 | 施錠信号は「信号線を GND に落とすと施錠するタイプ」。＋を信号線、−を GND につなぐ |

### 4.4 絶縁入力 ×3（J3）

| 項目 | 内容 |
|---|---|
| 回路 | J3 の IN＋ → 3.3k → PC817 の LED → IN−。LED と逆並列に 1N4148（逆接続の保護） |
| 受光側 | エミッタ＝GND。コレクタを 10k で 3.3V にプルアップして GPIO に入れる（信号ありで LOW） |
| GPIO | IN1＝GPIO33（ドア）、IN2＝GPIO35（予備）、IN3＝GPIO36（ACC） |
| LED 電流 | 6V〜16V で 1.4〜4.4mA |
| 異常電圧 | 35V（抑制後のロードダンプ）で LED 10.1mA、3.3k の発熱 338mW。1/4W 抵抗の短時間過負荷（2.5 倍、5 秒）の 625mW 以下 |

ドア信号（開くと GND に落ちるタイプ）は、IN＋を J1 の OUT（12V）に、IN−をドアの信号線につなぎます。

### 4.5 OBD-II（CAN）

| 項目 | 内容 |
|---|---|
| トランシーバー | U9 MCP2562FD（DIP-8） |
| ピン | 1 TXD←GPIO18、2 VSS、3 VDD=5V、4 RXD→GPIO19、5 VIO=3.3V、6 CANL、7 CANH、8 STBY |
| STBY | R15 10k で 3.3V にプルアップ → **既定は待機（受信のみ・送信しない）**。GPIO4 を LOW にしたときだけ通常動作 |
| 終端抵抗 | 付けない（車両側にあるため） |
| ファームウェア | TWAI 500kbps、ID 0x7DF に標準 PID（01 01 MIL と故障コード数、01 05 水温、01 0C 回転数、01 0D 車速、01 42 ECU 電源電圧）を 500ms 間隔で問い合わせる。受信フィルタ 0x7E8〜0x7EF。バスオフ時は停止 |
| デカップリング | C5（5V）、C6（3.3V） |

### 4.6 ブザー

GPIO13 → R13 1k → Q1 2SC1815 のベース（R14 10k でベースを GND に落とす）。コレクタに 5V の自励式電磁ブザー BZ1（UGCM1205XP、12mm）をつなぎ、D7 1N4148 で逆起電力を吸収します。
ON 時の Vce は 0.10V（飽和）、Ic は約 29mA です。

### 4.7 ESP32 のピン割り当て（`config.h` と一致することをスクリプトで照合済み）

| GPIO | 用途 | 方向 | 備考 |
|---|---|---|---|
| 25 / 26 / 27 / 32 | 出力 LOCK / OUT2 / OUT3 / OUT4 | 出力 | — |
| 33 | IN1 ドア | 入力 | ext1 でディープスリープから復帰 |
| 35 | IN2 予備 | 入力 | 入力専用ピン |
| 36 (VP) | IN3 ACC | 入力 | 入力専用ピン。Wi-Fi/ADC 使用中のグリッチ（既知の不具合）対策で 300ms のチャタリング除去。ext0 で復帰 |
| 34 | 電圧測定 | ADC1 | Wi-Fi 使用中でも使える ADC1 |
| 18 / 19 / 4 | CAN TX / RX / STBY | 出力 / 入力 / 出力 | — |
| 13 | ブザー | 出力 | — |
| 21 / 22 | I2C SDA / SCL | — | BME280（0x76/0x77）、MPU6050（0x68） |
| 17 / 16 | GPS への TX / GPS からの RX | — | UART2 9600bps |

起動設定ピン（GPIO0/2/5/12/15）は使っていません。

## 6. ファームウェアの要点

| 項目 | 内容 |
|---|---|
| 環境 | PlatformIO（espressif32@6.9.0＝Arduino-ESP32 2.0.17）、NimBLE-Arduino 1.4.3、ArduinoJson 7.2.1、Adafruit BME280 2.2.4 |
| 自動ロック | BLE パッシブスキャンでビーコン（MAC か iBeacon UUID）の RSSI を見る。−75dBm より強ければ「在」。−90dBm より弱いか受信なしが 30 秒続いたら「不在」。不在になったとき、ドアが閉まっていれば施錠パルス（400ms、ブロッキング）。開いていれば閉まった時点で施錠 |
| 通知 | ntfy サーバーへ JSON で POST（TLS、証明書検証なし＝setInsecure）。同じ種類の通知は一定時間間引く |
| 指示 | 指示用トピックを 30 秒ごとにポーリング（`/json?poll=1&since=`）。メッセージの先頭に暗証番号が必要 |
| 駐車モード | キーが「離れている」・ACC OFF・ドアが閉・処理中のものがない状態が 10 分続いたらディープスリープ。ドア（GPIO33 LOW、ext1）・ACC（GPIO36 LOW、ext0）で即座に、タイマーで 15 分ごとに起きる。タイマーで起きたときは 10 秒キーを探し、指示用トピックを 1 回読み、通知を送り切ったら眠り直す（最長 45 秒）。ドアで起きたときは 15 秒以内にキーが見つからなければ侵入として通知。眠る前に GPS に待機命令（MediaTek の PMTK161、u-blox の RXM-PMREQ）を送り、MPU6050・BME280 をスリープ、出力とブザーのピンを LOW に保持。指示の既読位置・駐車位置・毎日報告の日付は RTC メモリで引き継ぐ |
| 省電力（低電圧） | 11.5V 以下かつエンジン停止中ならディープスリープ。ACC かドアで復帰し、30 分ごとに電圧だけ見に起きる（Wi-Fi は使わない） |
| テスト | `lib/starter_logic` の判定ロジック（在・不在、ビーコン解析、チャタリング除去、NMEA、OBD 応答の解析、バッテリー診断）を PC 上の 16 件のテストで確認 |
| ビルド | 実機用バイナリのビルドは警告なしで通る（`secrets.h` がないことを知らせる意図的な警告を除く）。プログラム領域の 64% |

## 8. 既知の制約（設計上そうしているもの）

1. **24V でのジャンプスタート**：TVS（18.6V で導通開始）が電流を流し、F1 がトリップして装置は止まります。長く続くと TVS が壊れるおそれがあります。
2. **ロードダンプ（抑制なし）**：400W の TVS では吸収しきれません。車両側にロードダンプ抑制がある前提（現行車では一般的）です。
3. **出力の逆接続**：PC817 の VECO は 6V しかありません。出力の＋と−を逆につなぐと壊れるおそれがあります。双方向 TVS は 45V までは導通しないので、逆接続からは守りません。
4. **CAN ラインのサージ保護**：専用の TVS はなく、MCP2562 の内蔵保護に頼っています。
5. **USB と 12V の同時給電**：DevKit の互換品の中には USB の 5V と VIN が直結のものがあるため、USB で書き込むときは 12V を外す運用にしています。

## 9. 検証してほしい点

### 9.1 特に重点的に見てほしいところ

1. **電源ラインの TVS を 2 本直列にした妥当性**：P4KE15A ＋ P4KE6.8CA。クランプ 約 30.0V と DC-DC の上限 32V の余裕は約 2V です。補間による見積もりが妥当か、実際の車のサージ（ISO 7637-2 の pulse 1・2a・3a/3b、ISO 16750-2 の抑制後ロードダンプ）に対して十分か。
2. **駐車中の消費電流（バッテリー上がり）**：駐車モード（6 章）で、キーが離れて 10 分後からディープスリープします。見積もりは 12V 側で 5〜13mA（1 日 0.12〜0.3Ah）、駐車モードなしでは 50〜65mA（1 日 1.2〜1.6Ah）。**眠っている間の電流は実測していません**。大部分は DevKit の AMS1117 の自己消費・電源 LED・DC-DC M78AR05-1 の無負荷電流と見ていますが、M78AR05-1 の無負荷電流の値は確認できていません。この見積もりと、眠っている間に揺れ検知が働かない・指示が最大 15 分遅れるという割り切りが妥当か。
3. **出力回路で施錠できるか**：PC817 のオープンコレクタ（数 mA〜50mA、飽和電圧あり）で、この車両の施錠入力を確実に動かせるか。
4. **GPIO36（ACC）入力の扱い**：ESP32 の既知のグリッチ（Wi-Fi/ADC 使用中）に対して、300ms のチャタリング除去で十分か。
5. **MCP2562 の STBY の既定値**：10k のプルアップで、ESP32 の起動中・リセット中に CAN バスへ送信しないことが保証されるか。ESP32 の GPIO4 はリセット直後に内部プルダウンなどで LOW にならないか。
6. **出力 TVS SMBJ45CA と PC817X の VCEO 80V の関係**：クランプ 72.7V（Ipp 時）での余裕。

## 10. 再生成の方法

このパッケージの `scripts/` は読むためのコピーです。スクリプトはリポジトリの配置（`esp32_engine_starter/hardware/` に基板ファイルとスクリプト、`../src/config.h`）を前提にしているので、実行するときはリポジトリで行ってください。

```
cd hardware && ./build.sh
```

必要なもの：KiCad 7（`pcbnew` の Python と `kicad-cli`）、numpy、ngspice、zip、Chromium（プレビュー画像用）。

`build.sh` は次の順に実行し、検証で 1 件でも問題があれば止まります。
1. 生成
2. DRC
3. ピン照合
4. 機構チェック
5. 回路計算
6. ガーバー出力
7. 製造データ照合
8. 部品表
9. 原寸 PDF
10. プレビュー画像

ファームウェア：`pio run -e esp32dev`（実機用）、`pio test -e native`（判定ロジックのテスト）。
